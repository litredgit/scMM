# 实验室网页 UI 与部署

[返回文档索引](README.md) · [安装说明](01-installation.md)

该界面面向实验室内网的小规模使用：服务运行在安装 scMM 的本机，浏览器可以从本机、局域网或
已配置的 Tailscale 网络访问。它不承担公网暴露、多租户、用户注册或大规模任务调度。

## 当前可用功能

现已扩展为八页工作台；分析页、外部 JSON、历史层与 Linux/Windows 原生结果读取的完整说明见
[工作台使用与数据安全](13-workbench.md)。Windows 最小模式不启动 Linux 专有后台任务。

1. 从启动参数明确开放的服务器挂载目录中选择 mzML/mzXML；原始文件无需经过浏览器上传。
2. 显示文件大小、扫描数、MS level、RT/m/z 范围和仪器元数据。
3. 按 MS level 和 RT 范围查看总离子流图（TIC）。
4. 输入多个目标 m/z 与 ppm 容差查看 EIC；查看单扫描谱及细胞窗口/峰顶。
5. 按 m/z、RT 范围查看合并谱或平均谱；点击谱图上的点可回填 EIC 目标。
6. 交互缩放、悬停、SVG 图像转存，以及 TIC、EIC、谱图完整数据 CSV 下载。
7. 使用 Panel 文件浏览器在白名单目录内逐级浏览和选择文件；侧栏初始宽度可完整容纳浏览器，并可
   拖动右边缘调整宽度（双击边缘恢复默认宽度）。其余侧栏控件保持 Panel 默认尺寸和纵向布局，
   TIC/EIC 与下载区会随客户端宽度缩放或换行。
8. 数据与处理页提供均衡、灵敏、严格三个参数起点及高级参数；只有输入、参数和临时存储空间预检
   通过并明确确认后，才能提交处理。完成后先用任务临时结果显示质量图和下载，再让用户选择永久
   保存或明确放弃。默认保存位置是原始文件同目录下的 `results/`，也可在与原始数据浏览器相同的
   挂载范围内选择其他服务器目录。
9. Linux 上单机同时运行一个独立后台处理任务。关闭或重载浏览器不会中止任务，重新访问页面可从任务
   记录恢复状态和最新 100 KB 日志。
10. 处理成功后显示细胞事件、特征数、零值比例、总强度、检出率、PCA 和 UMAP；可预览质量表，
    并下载标准结果 CSV、质量 CSV、嵌入坐标及运行清单。

预览谱先把所选范围固定分成 2 万箱，以免调用正式处理使用的高分辨率插值拖慢交互。图中超过
浏览器合理负载的数据还会采用保峰下采样，仅影响显示；CSV 下载保留本次计算的完整分箱结果。

## 启动

只允许本机浏览器访问：

```bash
uv run --locked scmm-ui --storage "原始数据=/mnt/ms-data" --port 5006 --show
```

同时允许局域网和 Tailscale 访问：

```bash
uv run --locked scmm-ui \
  --storage "原始数据=/mnt/ms-data" \
  --output "处理结果=/mnt/scmm-results" \
  --storage "归档=/mnt/ms-archive" \
  --address 0.0.0.0 \
  --port 5006
```

然后从其他设备打开 `http://<主机的局域网地址或 Tailscale 地址>:5006`。Tailscale 路由和主机
防火墙不由 scMM 管理；应只开放实际使用的端口。若部署方式改变了页面的 WebSocket 来源，可重复
提供 `--allow-websocket-origin HOST:PORT`：

```bash
uv run --locked scmm-ui \
  --storage "原始数据=/mnt/ms-data" \
  --address 0.0.0.0 \
  --port 5006 \
  --allow-websocket-origin scmm-node:5006
```

## 存储目录边界

`--storage` 使用 `显示名=服务器路径`，可以重复。路径必须在服务启动时已经挂载并且可读；页面不会
接收客户端机器上的文件路径。
Linux 的 `/home/crs/data` 存在时另以“云盘”加入；保存仍须用户选择目录并确认，且挂载需可写。
当前云盘为只读挂载，未自动修改。Windows 可用 `--storage "云盘=D:\数据"` 指定本机路径。

输入选择有两层约束：

- Panel 文件浏览器以当前白名单根目录为导航边界，只允许选择匹配的 mzML/mzXML 原始数据文件。
- 读取前再次在服务层解析真实路径，拒绝 `..`、未知根目录、非 mzML/mzXML 文件以及指向根目录
  外部的符号链接。

以上两项针对原始谱选择器。处理结果另有目录/H5AD 选择器，仍验证真实路径和子文件链接；
含 pickle 的旧目录要求明确信任，不从浏览器上传或执行不可信数据。

处理任务先把完整结果写入该任务自己的内部暂存区，并直接从暂存结果生成质量图和下载；此时无需
提前选择永久保存位置。查看完成后，用户可以选择永久保存或勾选确认后删除临时结果。永久结果目录
受 `--storage` 的同一边界约束，不能通过 `..` 或符号链接跳出挂载根。页面默认使用
`<原文件所在目录>/results/`，也可以在结果目录浏览器中切换挂载根、选择已有目录，或把当前浏览
目录设为目标。默认的 `results/` 尚不存在时只会在点击保存时创建。结果名称只能是所选目录的直接
子目录，不能包含路径片段。因此，启动 UI 的系统账号必须对实际选择的结果位置拥有写权限；原始
谱文件本身仍只会被读取。

`--output` 使用 `显示名=服务器路径`，其第一个目录保存持久任务请求、状态、日志和尚未作出保存
决定的临时结果（`.scmm-tasks/`），并兼容旧版固定结果位置；目录必须已存在且可写。未提供时使用
启动工作目录下的 `results/`。永久保存后任务状态会指向新位置，并更新结果中的
`scmm-manifest.json`；选择放弃会删除临时结果，但保留任务状态和日志。

保存位置控件只列出服务器文件夹，不列出或接受单个数据文件。网页上的 CSV/JSON 单文件下载使用
带结果名称前缀的文件名，并由浏览器保存到客户端默认下载目录；它不改变服务器结果位置。点击永久
保存会把处理矩阵、元数据、质量 CSV、嵌入坐标和运行清单一起保存到
`<所选文件夹>/<结果名称>/`。

## 架构和演进边界

```text
浏览器 / Panel 会话
  ├─ 引导式步骤、下拉参数、图表事件和下载
  └─ application 服务
      ├─ StorageCatalog：挂载目录白名单与路径边界
      ├─ RawPreviewService：文件加载与会话内复用
      ├─ RawFilePreview：TIC / EIC / 合并谱纯数据结果
      ├─ ProcessingPlanner：参数、输入、输出冲突与容量预检
      └─ ProcessingTaskManager：单任务锁、原子状态、日志与独立 worker
          └─ PyOpenMS 与既有 scMM.file 谱处理
```

界面层不实现科学计算算法。这样可以独立测试数值和文件权限，也可在不改底层流程的情况下调整
Panel 页面。

原第三个引导页的处理功能现已分布到“数据与处理”和“任务与日志”页：

1. 处理参数预检，并把实验相关参数组织为少量预设加高级选项。
2. 使用单机后台进程执行 `CyESIData` 工作流，显示并恢复任务状态和日志；不引入集群队列。
3. 先在任务暂存区生成结果和网页质量检查，再由用户决定是否保存；保存目录必须位于原始数据挂载
   白名单内，并生成参数和软件版本清单。
4. 后台生成细胞/特征质量表、PCA 和 UMAP 坐标，页面重连后直接读取持久化文件。

嵌入仅用于初步质量检查：超过 10,000 个细胞时等距确定性抽样，超过 2,000 个特征时选择对数
强度方差最高的特征，并把这一行为写入质量提示。UMAP 使用固定随机种子；缺少可选依赖或 UMAP
失败不会把已保存的原始处理结果误标为失败，PCA 和基础质量表仍然可用。

任务结束后页面提供独立文件下载，而不会在服务器上额外复制一个可能很大的压缩包。完整结果已经
位于所选服务器目录，适合由现有的数据存储服务器直接归档或转存。

计算任务将与 Panel 回调分开，避免浏览器断开导致处理被中止。实验室规模下可以先限制同一时间
运行一个重任务，待实际使用出现并发需求后再增加队列，而无需预先部署复杂调度系统。

## 更新代码后网页仍是旧界面

常驻 Python 服务不会自动重新导入更新后的代码。Git 提交、更新文件或刷新浏览器不等于
更新正在运行的进程。若页面仍只有旧的三个标签，先核对端口对应的进程、启动时间、工作目录和环境。

本机使用用户级 `scmm-ui.service`，检查方式：

```sh
systemctl --user status scmm-ui.service --no-pager
systemctl --user show scmm-ui.service -p ExecStart -p WorkingDirectory -p MainPID -p ActiveEnterTimestamp
journalctl --user -u scmm-ui.service -n 30 --no-pager
```

确认没有进行中的任务，并先保存需要保留的会话结果后，重启该服务加载代码：

```sh
systemctl --user restart scmm-ui.service
systemctl --user status scmm-ui.service --no-pager
```

重启会断开网页连接并清空未保存的会话分析，但不删除已保存文件。只有修改 service 文件时
才需要先执行 `systemctl --user daemon-reload`；只修改 Python 代码不需要。
随后重新打开原地址或刷新页面，检查八个工作台标签。HTTP 200 本身不足以证明已加载新版，
还应检查实际页面或 WebSocket 文档的标签。

2026-09-28 本机实例已核实：原进程自 09-21 启动，在线仅三个旧标签；重启后同一 5006 端口
返回八页工作台和云盘选项。启动配置中的通配 WebSocket origin 仍有安全警告，未自动改变现有访问策略。
