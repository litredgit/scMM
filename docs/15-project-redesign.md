### 已知限制与后续待办

- 内部快照不自动清理，重复保存增加磁盘占用；仅暴露一个当前版本，不等于只留一份物理文件。
- 分析及单样本检测预览仍同步执行，大样本可能阻塞该会话；只有批量提取是持久后台任务。
- 每项目只能运行一批任务，但尚无跨项目资源队列；不要同时提交大量项目。
- 参数编辑没有浏览器关闭拦截/自动保存；应用内切换项目有未保存确认。
- 嵌入/聚类不能覆盖已有输出键，需新名称；DBSCAN 的 eps=0.5、min_samples=5 及图聚类
  resolution=1 暂为固定值，页面已明示。
- 导出提供 H5AD、表格、图和 JSON 摘要，尚非一键排版的 PDF 实验报告。
- 旧结果不自动迁移或删除；真实大批量生物数据、厂商 RAW、Windows 实机及断电恢复仍需验收。
- 轨迹方法、R2/Q2 继续暂缓，原因与决策选项见 [暂缓算法说明](14-deferred-methods.md)。

## 运行问题修复（2026-09-29）

- 在线项目 `corwithchang` 的三个批次均在 worker 启动时读取 `request.json` 失败。日志证据为
  `UnicodeDecodeError: ascii codec`，中文存储标签“原始数据”是首个非 ASCII 字段。
- 根因是用户级 systemd 服务未提供 locale，后台 Python 默认文本编码为 ASCII；网页进程将请求正确
  写成 UTF-8，但 worker 使用了平台默认编码读取。状态来不及从 queued 改为 failed，页面轮询后
  显示推断状态 `Worker no longer running`。
- 后台任务的所有 JSON 文件现显式按 UTF-8 读取；启动阶段异常也会写入 failed 状态。强制
  `LANG=C`、`LC_ALL=C`、`PYTHONUTF8=0` 的独立进程中文任务测试通过。
- 分析页的“先审核建立数据集，或导入已有结果”是当前项目尚无数据集时的正常门禁。任务成功后仍需
  在“提取与审核”页选择成功样本并点击“确认纳入并建立当前数据”，然后才能进入分析。
