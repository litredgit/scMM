## 正确性与兼容性

### REV-01：reset 后的强度溯源（P1）

**合成 H5AD 往返复现**：对含零值矩阵做 median 插补，保存 H5AD，再用
`AnalysisWorkspace.replace()` 导入。此时 `dataset_inputs(data, "X")` 正确拒绝已插补强度；
执行 `reset()` 后矩阵不变，却被接受为原始强度，`intensity_layers()` 也把 X/reset 层列入 raw。
普通项目重载有独立 baseline，不能把该问题扩展为所有项目 reset 都错误。

定位：[强度检查](../scMM/util/lipid_annotation.py) 的 `validate_intensity_layer()`、
[网络层判断](../scMM/util/lipid_network.py) 的 `intensity_layers()`、
[工作区](../scMM/application/workbench.py) 的 `replace()`/`reset()`、
[项目重载](../scMM/application/projects.py) 的 `open()`。

实施建议：共享可独立验证的强度溯源计算，恢复起点携带真实处理状态，reset 恢复该状态。
区分未变换强度、仅归一化强度、已插补/其他变换和未知来源；具体存储字段与迁移在本项设计。
旧 H5AD 不能仅凭非负值、层名或 reset 操作推断为 raw；信息不足时明确兼容策略，不静默伪造来源。

验收：原始/已归一化/已插补数据分别走导出→导入→reset/restore；矩阵、层及来源判断一致。
注释和网络可选层、后端检查、保存重载使用同一规则；失败不污染当前数据。
相关测试：[脂质领域](../tests/domain/test_lipid_annotation.py)、[网页脂质](../tests/api/test_web_lipids.py)、
[工作区](../tests/application/test_workbench_state.py)、[项目](../tests/application/test_projects.py)。

### REV-02：quantile 并列值（P1）

**合成数值复现**：`[[0, 1], [0, 4], [0, 9]]` 经 quantile 后，原全零特征变成
`[0.5, 2, 4.5]`；细胞重排后再还原顺序，结果不一致。
[实现](../scMM/util/normalize.py) 的 `norm_quantile()` 使用两次 argsort 给并列值分配不同排名。

先确认并列值与稀疏零值的科学处理规则，再实施；不能顺带改成按细胞行归一化。
当前按特征列计算的方向已经写入[参数文档](parameters.md#归一化)。
零值是否保持为零需单独论证，不能以修复排序为由改变全部归一化语义。

验收：同一特征内并列值的处理一致；细胞排列改变后对应结果不变；非并列输入、常量列、
全零矩阵和重复细胞有数值对照。同步参数说明和数值变化记录，保留旧产物的处理来源。
相关测试：[归一化](../tests/domain/test_normalize.py)、[工作区](../tests/application/test_workbench_state.py)。

### REV-03：旧目录覆盖保存失败（P1）

2026-10-21 修复已获用户验收通过；本机检查与发布证据见 CHANGELOG，当前协议见
[旧目录保存说明](data-output.md#保存目录)。以下保留原故障依据及验收条件。

**临时目录故障注入复现**：先保存一份数据，再同时修改矩阵和分组；在
`save(overwrite=True)` 写 `peak_meta.pkl` 时抛 OSError。重新加载仍成功，但得到新矩阵和旧分组。
定位：[旧目录保存](../scMM/file/_dataset_interop.py) 的 `save()`、
[读取](../scMM/file/_dataset_loading.py) 的 `load_processed_dataset()`。

实施建议：完整候选产物写入及验证后再发布，设计与旧读取路径兼容的覆盖/恢复协议。
非空目录覆盖、并发读写、同文件系统与云盘行为须明确；不能只把逐文件 replace 称为整个数据集原子发布。
不改变 `save()` 返回实际目录、默认防覆盖和旧格式兼容，不影响已有网页项目快照协议。

验收：新建及覆盖在任意关键写入点失败，旧完整版本仍可恢复或明确拒绝不完整产物，
绝不静默读取混合版本；检查并发覆盖、可选 SNR 旧文件清理及临时产物恢复。
相关测试：[数据](../tests/domain/test_data.py)、[H5AD 互操作](../tests/domain/test_h5ad_interop.py)、
[处理任务](../tests/application/test_processing_tasks.py)。真实云盘中断专项已按用户要求取消，不将本机故障注入视作云盘验证。

### REV-04：Python 变换后的分析产物失效（P1）

**合成复现**：带 `X_pca` 及其参数的 AnnData → `CyESIData.from_anndata()` →
`normalize("total")` → `to_anndata()`，X 已改变，旧嵌入与参数仍保留。
定位：[处理门面](../scMM/file/_dataset_processing.py)、[模板互操作](../scMM/file/_dataset_interop.py)。

实施建议：区分纯往返、轴裁剪、矩阵变换及元数据修改；矩阵变换统一处理已知下游结果，
保留应保留的原始层、来源及稳定 ID。不要简单删除整个导入模板来绕过生命周期设计，
也不能假设任意外部 uns 键都能自动判断依赖；对未知分析产物明确保留/失效策略。

验收：normalize/impute/离群/去同位素等有关入口分别核对当前矩阵、轴、层、嵌入、图与报告；
无变换往返继续保留原有互操作信息。网页和 Python 的同类操作具有一致的科学解释，失败保留旧状态。
相关测试：[H5AD 互操作](../tests/domain/test_h5ad_interop.py)、[数据](../tests/domain/test_data.py)、
[工作区](../tests/application/test_workbench_state.py)。

2026-10-18 审阅时，`run()` 忙时直接返回，异常也被内部处理，调用方可能把未执行当成链路已结束；这是历史问题定位，当前执行结果与保护范围以[roadmap](roadmap.md#已验收的工程与交互改进)和[开发契约](development.md#操作返回值与完整互斥链)为准。

此处是竞态风险定位，不是已完成浏览器压力复现。

建议统一明确的执行结果及操作状态，区分未执行、失败、成功及结果已计算但展示失败；

不默认将全部请求塞进全局队列，不自动重放超时写入，不增加确认复选框或二次确认弹窗。

验收：连点、回车和切页不重复写入或串项目；完整链只提示一次成功；无关读取不覆盖操作错误；
任何按钮的不可用原因可理解，分析页已验收行为继续通过。

### FE-02：串行轮询、请求身份和页面生命周期

对应 UX-03。入口：[预览任务所有者](../frontend/src/features/raw/composables/useCellPreview.ts)、ExtractionPage 的 refresh、store 心跳、
[统一轮询调度](../frontend/src/api/polling.ts)和[请求客户端](../frontend/src/api/client.ts)。原审阅中的异步 setInterval/仅卸载清理已纳入该调度范围；当前契约见[开发指南](development.md#前端轮询调度与页面代次)，其他异步入口继续按以下条件审计。

建议上一轮完成后再调度，合并重复状态读取；成功与失败都核对工作区/项目/数据身份及请求代次。
同一修订下的先后请求仍可能乱序，不能只比较 revision。定义 KeepAlive 停用、恢复和项目切换的行为，
区分页面展示轮询、全局任务状态与后台任务本身；离开页面不能误报取消计算，也不能丢失已完成任务的接收入口。

验收：延迟大于轮询间隔时至多一个同类状态请求在途；旧成功/旧失败不更新新页面；
切页恢复、任务结束、断线和工作区过期有明确行为。浏览器覆盖任务已完成但尚未接收的状态。

### FE-03：按状态职责拆分功能页面

对应 UX-04，结合 MOD 项。优先 RawPage 和 LipidPanel/LipidNetworkPanel，随后检查 ExtractionPage。
分析页已有页面外壳、模块面板、设置与执行组合函数，不把它重新列为尚未模块化。

建议 RawPage 分离参数草稿/应用、原始谱查看/扫描导航、预览任务；脂质页面分离版本/规则、
查询筛选/分页、候选/同位素审核及网络展示/导出。页面外壳负责组装与导航，
组合函数拥有异步请求与状态，小组件通过明确 props/events 交互；一个任务和一份表单只有一个状态所有者。
避免拆分后各组件分别注册轮询或重复加载配置，避免用更多跨组件 watcher 代替清楚的数据流。

验收：项目/数据/注释版本切换准确重置；同项目按既有约定保留草稿，草稿与已应用值可区分；
改显示设置不清统计结果，改科学输入清对应结果；原默认值、导出精度和主动保存不变。

### FE-04：窄屏、可访问性与绘图性能

对应 UX-02/04、PERF-01。首页长路径表格的手机溢出已有历史复现，须在当前版本重新检查。
审阅时 Plotly 静态分块约 4.79 MB（未压缩），且已有延迟加载；文件大小不是渲染耗时证据。

建议让长路径、表格和图形在各自容器中换行/滚动，保持关键信息和下载可达；
帮助同时支持悬停与键盘焦点，状态提示可被辅助技术识别；检查助手浮层是否遮挡主操作、键盘焦点及关闭入口。
测量首次绘图、切换/重绘、浏览器内存、JSON 传输和大表查询，再选择裁剪图形依赖、复用数据或渲染优化。
显示抽样/分页不能截断下载，显示格式不能降低计算或导出精度。

验收：1440/700/390px 的真实交互与键盘流程通过；表格内部滚动不造成整页溢出；
报告输入规模与前后性能，而不是仅列 bundle 大小。图形失败可诊断与重试，页面无未捕获错误。
